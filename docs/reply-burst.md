# 连续消息合并回复

人设 SSOT：`data/persona_dossier.json`。微信 iLink 与 QQ OneBot 的正式收信入口对 demo_contact 使用同一等待算法：

- 常规单条入站后安静 6 秒再生成；同批达到 3 条，或最近已处于活跃/密集聊天时，安静窗口缩短为 2 秒，单次收集最多 12 秒。
- 新消息重置安静计时，但不延长收集总上限。关闭 `reply.engagement.enabled` 可回退原来的 6/10 秒安静窗口和 45 秒上限。
- QQ 收信回调只入队，单 worker 串行处理；微信继续使用原 feeder/worker。
- 同一批按原顺序合成一轮输入，图片与语音逐条先做原有理解，再一起给模型；聊天库存储合并后的完整正文。
- 活跃/密集聊天或热情陪聊时先完成当前短文字回复，新消息留在队列下一轮处理，避免持续输入反复取消导致一直无回复。图片/语音、常规低频、需要收口的睡聊仍使用取消机制；已发出的气泡不撤回。有新入站排队时先处理对话，延后旧 outbox 补发。
- 收集上限不包含模型和网络耗时，不是承诺发送时限。

## 跟随对方聊天节奏

`src/reply_engagement.py` 按合并前的真实入站计数，跨多轮回复累计；同一条消息重试不重复加分。`STATE.reply_engagement` 保留最近3分钟的消息 ID 哈希和时间戳（最多128条），另存本段聊天起点，不存聊天正文。消息权重每60秒减半，加权总数≥2.5为活跃、≥5为密集；零散旧消息及重放的历史积压不会当成即时热聊，停聊后自然回落。

- 合并的6条消息仍向模型传入6条的真实计数；一条消息内部换行不会虚增条数。
- 生成前选择回应方式，同时传入内容要求和预算。热情陪聊要具体回应内容与感受、给出自己的反应并自然延续，不能靠拆气泡充数。统一允许最多8气泡、120字，即使本轮只有1条，也不再按来信数量压低预算；允许简洁，不强制凑数。常规分支保留原比例预算和80字上限。
- 热情陪聊额外拟人等待最多2秒，密集时最多1秒；气泡间隔分别0.5–1.2/0.35–0.85秒；模型已耗时会抵扣额外等待。
- 晚间被动回复的热情模式覆盖睡前/已睡的裁短与慢间隔；明确告别仍自然收口。主动任务不使用这套回应方式，不改变主动联系配额与睡眠门槛；普通回复本来就不占主动额度。
- 不根据消息频率推断情绪或抬高亲密度；内容仍按对方实际表达回应。

## 白天实习选择器与晚间优先级

时间按 Asia/Shanghai，`reply.engagement.day_start_hour=7`、`evening_hour=17`。

| 条件 | 回应方式 |
|---|---|
| 明确道晚安或结束聊天 | 自然收口；“别说晚安，我还想聊”不算告别 |
| 17:00至次日07:00收到来信 | 必须热情陪聊，无需先达到高频阈值；夜间实习也不抽签 |
| 白天高频，当前实际日程为实习 | 30%热情陪聊，70%沿用常规节奏 |
| 白天高频，其他活动或日程未知 | 直接热情陪聊，不因一般忙碌进入选择器 |
| 白天低频 | 沿用常规节奏 |

实习资格只取 `schedule_fidelity.resolve_slot` 返回的有效 `work_internship` 槽，遵循当天日程、时间边界及执行状态；不按“忙碌”强度或关键词猜测，不沿用过期 `life_now`，未落实/取消的实习不参与。概率配置为 `internship_enthusiastic_probability=0.3`。按联系人、日期、当前槽和连续聊天起点做稳定均匀抽样，同一槽内连续聊天不重抽；静默超过3分钟后新一段聊天重选，换槽也重选，进入晚间直接覆盖。概率是长期抽样比例，不是每10轮强制3轮。

`reply_engagement` 调试信息包含 `response_mode`、`reason`、`selector_applied` 及抽样值，便于核对；这些信息不作为微信正文。热情不改写日程事实，也不自动抬高亲密程度。关闭 `enabled` 会关闭本节回应方式选择，恢复原回复策略。

不自动补发历史未回消息。纯函数计时与假传输测试见 `tests/test_reply_burst.py`，不会真发或读写真实联系人状态。
