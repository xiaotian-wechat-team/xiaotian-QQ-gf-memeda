# 分享不重复发送设计

人设事实源：`data/persona_dossier.json`。仅处理 demo_contact 的主动 `surf_share`，普通聊天续聊不受影响。

## 内容身份

- 小红书 explore / discovery/item 归一为作品 ID；抖音 video / note / modal_id 归一为作品 ID，忽略这些作品链接的分享参数。
- 其他链接保留内容参数，仅去常见追踪参数和 fragment；短链接不主动联网解析。
- 图片按文件字节 SHA-256 识别，保存指纹后即使素材过期删除仍有效。裁剪、重新编码不保证匹配；不会以标题相似误伤新作品。
- 不把素材库整数 ID 当永久身份（库清理后可能复用）。原有当日 ID 排除保留。

## 两层闸门和持久状态

`STATE.share_dedupe` 是独立、跨日、不截断的身份账本，不受最近 40 条 shares 续聊记录淘汰影响。键为 URL/图片指纹，值保存 owner（主动轮次 ID）、状态和时间。

1. 选材时排除账本与旧 shares 记录中的内容；池里没有新内容就不分享。
2. 发送前重新检查，并在联系人文件锁内原子占用；在第一条配文、链接、图片发出之前落盘。换文案或换新队列 ID 均不能绕过。
3. 成功回执把身份标为 sent。发送失败或进程中断保留 reserved，优先避免重复，可能牺牲一次未真正送达的分享。重启 worker 不重放原轮次；仅该轮次已有 outbox 可继续未发送后缀。
4. iLink/QQ outbox 重试也核验身份归属；其他轮次的同一内容直接 dropped。现有 worker/outbox 进程锁串行化发送。
5. dry-run 不占用身份。--force 不绕过内容去重。

## 上线迁移

备份 demo_contact STATE、主动队列和 outbox 后运行：

```
.venv/bin/python tools/migrate_share_dedupe.py
```

迁移持有 worker 锁，把旧 shares、主动队列 sent/hold、outbox 已发送/待确认的主动分享并入账本。只写分享账本，不改聊天正文、不清空计数、不发消息。没有历史记录的旧分享无法凭空恢复；历史短链与长链别名、重新编码图片仍有识别边界。

proactive 每次为新进程时自动加载；常驻 onebot / ilink 需在无正在发送任务时串行重载，才能加载补发闸门。验收使用临时目录的离线测试，不以真实分享测试去重。

## 回归

`.venv/bin/python tests/test_share_dedupe.py`：跨日、URL 参数/路由变化、素材 ID 变化、同图异路径、素材删除、崩溃后 worker 不重放、原轮次补发、历史迁移、选材排除、发送前丢弃、普通聊天不受影响。

## 题材多样性（2026-10-27）

作品去重之后，再使用 `src/share_selection.py` 做题材抽样。候选同时合并检索结果与每个平台最近 300 条，按平台/URL 合并，排除过期、无图、无原链及已分享内容。避免原来 recent(12) + 固定最高分把一批滑雪依次发完。

标题、正文、tags 经显式题材别名识别（崇礼、雪如意、翠云山、单双板统一滑雪）；未知题材按有效标签归组，无标签归“其他”。这是轻量规则分类，不是完备语义模型；别名未覆盖的题材可能漏分，多题材按规则优先级归组。

对候选 i，基础权重 `b_i = exp(clamp(score_i, 0, 4) / 2)`。题材 t 的近期曝光为 `E_t = Σ 2^(-距发送小时/24)`，只统计最近 7 天已成功分享。题材总权重为 `W_t = mean(b_i in t) × exp(-1.5 E_t)`，按 W 归一化，再在组内按 b 抽取。采用均值而非求和，避免库里某类数量多就淹没其它题材。

若最近一次分享距今不超过 72 小时，该题材下一次选材的概率总和封顶 2%；其余概率分给其他题材。若只有同题材可选，剩余至少 98% 是跳过，不强行归一化回 100%。同一天、同分享历史复用随机数，避免每五分钟重抽把小概率变成必发。新素材导致候选变化仍可能改变结果；2% 是单次分布上限，不是整个时间窗的累计概率承诺。

成功分享记录保留 `share_topic`、tags；队列 material 记录 `selection_probability`，便于复核。旧历史用现有标题推断题材。此前作品 URL/图片硬去重、联系人限制和发送间隔继续生效。

验证：`tests/test_share_selection.py` 覆盖滑雪同义题材、200:1 库存偏斜仍封顶 2%、只有同题材时跳过、题材数量平衡、历史曝光衰减、同日不反复抽签和搜索命中仍扩充候选。

## 内容结构与出游邀约（2026-10-27 用户调整）

分享库按“有效作品原链 + 本地图片”的可发素材计数，目标轻松内容占 50%，其余内容共 50%；减少学校占比，以增量补充为主，不删除历史。轻松组必须有明确题材：梗/幽默吐槽、游戏、萌宠、穿搭美妆、拍照审美/日常好物，符合 persona_dossier 的年龄与个性；未知标签不自动算轻松组，不因性别假定她玩过某游戏。非轻松题材包括学校、旅行、滑雪、舞蹈、影视等。采集需要真实作品链接与实际图片，搜索页壳链不计入达标数。

选材基础份额按 light 50% / school 5% / other 45% 分层，在各层内继续使用题材均值与近期曝光降权。2% 连续同题材上限仍优先；只在同层内分配剩余概率，不跨层抬高学校概率。缺某层时该层概率留作跳过，因此实际有限轮次或冷却期间不保证恰好 50%，也不能用权重达标替代库存达标。

旅游/滑雪/逛展及明确出游、探店、游乐园等分享进行纯函数邀约抽样：基础 p=0.35；近 12 小时已有成功的邀约分享则 p=0；否则 `p=0.35×0.4^I`，I 为最近 7 天邀约曝光（48h 半衰期）。同日、同作品、同分享历史复用抽签；选材结果与队列保存 invitation 决策；仅发送成功后写入 shares，失败/dry-run 不扣冷却。

抽中时任务提示要求结合地点自然表达想一起去；未抽中明确禁止附邀约。不能约定未确认日期、订票或行程。此控制针对生成提示，不是对自由文本做机械句子拼接；模型是否严格遵循仍须观察。未触发真实发送测试。

后续采集也使用 `collectors/topics.py` 的 50/5/45 搜索方向权重，替换抖音/小红书原来以北舞、编导生、校园为主的默认列表；显式指定 topic 仍原样执行。采集方向概率不是入库质量保证，每次仍按有效原链/图片和实际内容审计库存比例。
