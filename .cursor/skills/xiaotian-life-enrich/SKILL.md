# 小甜日程补充 Agent

先读 `data/persona_dossier.json` 的 `usage.enrich_must_read`（尤其学校、社团、作息和实习），再读目标日期前后至少 7 天的日程、`data/study_blocks.json`、活动池与用户约定。不得编造档案中未定义的身份、公司、项目或生平。

你负责从灵感到可执行日程的完整补充。独立「日程 review Agent」已删除，不能再调用、创建或转交给它；也不能调用 Cursor 做第二轮日程审查/改写。写入前直接运行本地规则校验，失败时由你修正。

## 晚间排程提示词

- 学期内，在有可用空档的工作日每周安排 **1–2 晚外出**，周一到周五都可选。先排课、排练、实习、社团例会、用户约定和睡眠，再从空闲晚选择；疲劳越高，外出权重越低。晚实习后留休息，不能为了凑次数挤出门。
- 先读 `data/evening_activities.json` 的 52 个细化模板，不再只写“逛街/看电影”大类。短活动以逛街试衣/文创配饰、看橱窗倒影/楼宇夜景、KTV合唱、桌游/手作为主；电影按片种与散场交流细化。仅首次排空闲晚时按大类选取，再选具体内容，不能让模板数量决定大类概率；已落盘的日期/活动不因扩库重抽。
- 校园散步仅少量点缀：大类基础权重约2%，重复降权后也不能被抬升为主菜；核对近14天，同一具体活动避重，最近一次的大类显著降权。短活动30–90分钟；时长不含往返。
- 偶尔安排电影、小剧场演出，给活动本身 90–150 分钟及必要交通。开场时间、营业时间和路线未核实时只能作为待定计划，不能编造已购票、已预约或具体场次。
- 已有晚间实习槽可以安排夜间拍摄：色温/光影与机位备注、橱窗倒影空镜、环境声与固定机位、外景补光记录、楼宇亮灯与素材备份。仅丰富现有晚实习，不另加工作天；在同一时间预算内写去程、工作、返校，不推迟睡眠，不虚构公司/项目/客户。
- 每个新模板带 `scene_id`、具体 `scene_hints` 和拍照边界，复用 outfit → scene_refs 路线；素材为环境参考，不代表真实到访或许可。观影期间不拍，电影图用入场前或散场后大厅；工作图仅休息间隙，不拍项目资料或他人正脸。
- 保留整晚休息。休息晚可自然混合写作业、整理照片、画两笔、看剧、听歌、和室友/男友闲聊；不要每天固定几个小时只写「宿舍刷剧」。周末通常只选一晚外出（每个周末80%概率安排一晚），其余晚休息；白天玩得久或有出差时优先休息。
- 对照前后一天，**同一活动不要连续两晚**；不得把每周外出固定在周三/周五，也不要每天重复同一家店或同个题材。
- 每次本地外出分别写去程、活动、返程和回寝后空档。学校附近按步行预算；跨城区按保守交通预算。不得把整个晚间全部留给活动，回来后还要有洗漱、睡觉时间。不要为了娱乐推迟既有睡眠。

代码入口为 `src/evening_plan.py`；`life_calendar.generate_day` 和已落盘晚间更新共用此规则。外出组用 `outing_id`、`city=北京`、`leg=outbound/activity/return`，不要套用实习出差的 `trip_id`。

## 具体计划，不能只有活动标签

- 每次必须包含目的、拟同行（从人设档案选择，未确认不能说已约好）、集合点、候选街段/场所、去程与最晚回寝时间。未核实的门店与影厅不编造名字或场次。
- 用 `itinerary` 写至少三段起止时间和具体动作，完整放在原活动槽内，例如看发夹→试两种颜色→比较舒适度。电影须容纳完整片长、候场、散场和往返；放不下就取消，不靠中途离场或推迟睡眠迁就模板。
- 附具体 `photo_subject` 与细分 `scene_id`：试衣镜、发夹柜台、明信片架、串珠托盘、窗边热饮、影院检票走廊等；品牌/水印不得照搬，参考图不证明到过该地。
- 不逐日重新掷骰子。已排计划细化用 `--details-only`，保留全部日期、活动、时刻；空闲次日晚可条件性整理前晚照片/笔记，但前晚未成行就不声称完成。
- 核对门店营业/场次、同行、天气与交通预算，超时或天气不合适就休息；仅雨后活动要等雨停且路面安全。

## 地理与时间约束

- 小红书/抖音标题只作灵感。不能直接替换早餐、午餐、晚餐、洗漱、睡眠、课业或实习槽；不能把旅游帖子当成当天真实经历。
- 禾木、梅里雪山、三亚、国外旅行等必须安排**完整多日弧**：出发前所在地、去程、接驳、连续停留、住宿、返程、返校。读取活动池的最短停留和交通预算；未知时长先补全，不得默认零交通。
- 禁止「下午禾木—晚上校园演出—睡前梅里雪山」、一天往返远途、当地游览与长途交通重叠。人在外地期间不能插入北京上课、食堂或回宿舍。
- 完整旅行弧用匹配的 `activity_id` 和独立 `transit_day`；实习出差遵守 `config/schedule_review.json` 与 `src/schedule_travel_review.py`。单日兜底生成器只生成北京本地活动，不自行抽长途目的地。
- 时间段按先后连贯、不能重叠，覆盖到 24:00；到入睡时刻之后应是「睡觉」。考试/答辩/复习硬块优先。
- 冻结月份和用户已确认的单独约定默认保留。用户明确要求修改的范围可以更新，同时记录原因；不能借此重写过去的经历。

## 调研与执行

优先补充低成本、短时间、北京本地的活动，再按季节补充周末和假期旅行灵感。只读采集，必须走 `source_poll` 和 `data/collectors.lock`，不绕登录墙/验证码，不点赞评论关注，不输出 Cookie/凭据。默认采集词见 `tools/enrich_life_from_research.py`。

```bash
# 可选：调研入池
.venv/bin/python tools/enrich_life_from_research.py research --force
.venv/bin/python tools/enrich_life_from_research.py upsert-pool
# 活动池缺时长时补全；仅补池，不审查或改写日程
.venv/bin/python tools/update_month_schedule.py pool-duration
# 月更：本地规则校验通过才写入并冻结，没有 --agent
.venv/bin/python tools/update_month_schedule.py plan --month YYYY-MM
.venv/bin/python tools/update_month_schedule.py apply --month YYYY-MM --inject-research --freeze-after
# 全日程本地校验
.venv/bin/python src/reasonableness.py --all-days
# 同步到允许的联系人 demo_contact；不启动聊天 daemon，不发送测试消息
.venv/bin/python tools/update_month_schedule.py sync --cid demo_contact
```

自动调研注入只给已安排往返的本地活动附加 `research_inspiration`，不改地点/活动名/时间；由补充 Agent 核实后整体排程。必要时可用 `--pool-duration --agent` 补活动池时长，这是补充任务，不得扩展到日程 review。

已获用户指示修改未来晚间时，可用 `tools/update_evening_schedule.py --from-date YYYY-MM-DD` 预览，加 `--apply` 写入；用户明确覆盖冻结月份时加 `--include-frozen`。不启动 OCR 微信、WDA 或真发测试。

验收：本地日程校验通过；同日没有跨城跳转、饭点/洗漱被覆盖；每周外出频率合理，往返齐全，已确认行程和过去记录保持可追溯。参考图缺失可用 `tools/queue_scene_refs.py` 排队，不阻塞日程本身；素材和生图仍遵守人设档案。

## 2026-10-28 最小修复

- 实习每周从合格工作日随机抽2–4天（日期种子稳定），每天仅一个半天/晚段；室内外均衡，正常周至少一个晚段外拍，往返放在工作预算里。考试/已确认约定/课业/睡眠优先，不为凑数加周末工作。
- 排入新模板仅替换少量同类别旧活动，不整体重抽；步骤按具体分钟预算，空余写慢逛/休息；宿舍单一休闲段不超过90分钟。
- 电影/KTV等需实际场次或门店的活动 execution_status=pending；核实地点/营业、完整片长或包间时段及往返后才设confirmed。cancelled或pending的活动在运行时退回宿舍休息，不报备到店、不生成该场所照片。普通本地自由活动用scheduled，仅代表虚构人物日程，并非真实预约。
